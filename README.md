# NL_2026

Индивидуальная работа: 20 программ на 20 разных языках программирования.
Пять тем, на каждую тему - по 4 программы

## Языки

Ada, D, Elixir, Groovy, Haskell, Julia, Lua, Kotlin, ML, Mojo, Objective-C,
ODIN, Perl, Ruby, Rust, Scala, Scheme, Erlang, Zig, Lisp

---

## Тема 1. Многопоточность

Папка: `1_threads/`

| № | Задача | Язык | Папка |
|---|--------|------|-------|
| 1 | Параллельный подсчет простых чисел на отрезках | Ada | `task_1_ada` |
| 2 | Параллельный поиск по файлам через каналы | Rust | `task_2_rust` |
| 3 | Задача о философах за столом | Elixir | `task_3_elixir` |
| 4 | Параллельные банковские переводы с проверкой инварианта | Kotlin | `task_4_kotlin` |

1.1 **Ada.** Отрезок [2, N] делится на 4 части; каждая часть
обрабатывается в собственной Ada-задаче (task) тривиальным тестом на
простоту. Найденные простые числа складываются в защищенный объект
(protected type) - он держит мьютекс внутри. Главная программа
дожидается каждой задачи через второй рандеву (`Finish`).

1.2 **Rust.** `mini-grep`: каждая пара (файл, шаблон) обрабатывается
отдельным потоком `std::thread`. Найденные совпадения уходят в главный
поток по `std::sync::mpsc::channel` (multiple producers, single
consumer). Main собирает результаты, сортирует и печатает.

1.3 **Elixir.** Модель акторов: 5 процессов-вилок и 5 процессов-
философов, общающихся только сообщениями. Философ сначала пробует
взять левую вилку, потом правую; философ №5 берет их в обратном
порядке - это классическое предотвращение взаимной блокировки
(circular wait).

1.4 **Kotlin.** 5 счетов и 4 потока, каждый делает 1000 случайных
переводов. Каждый счет защищен `ReentrantLock`; порядок захвата
фиксирован по `id` (первым берется меньший) - это исключает deadlock.
После работы всех потоков проверяется инвариант: сумма балансов равна
начальной.

## Тема 2. Алгоритмические задачи

Папка: `2_algorithms/`

| № | Задача | Язык | Папка |
|---|--------|------|-------|
| 1 | Рекурсивный разбор и вычисление арифметических выражений | Haskell | `task_1_haskell` |
| 2 | Бинарное дерево поиска: вставка, обход, высота | Scala | `task_2_scala` |
| 3 | Рекурсивное решение задачи о Ханойских башнях | Scheme | `task_3_scheme` |
| 4 | Рекурсивный перебор задачи о N ферзях | Lua | `task_4_lua` |

2.1 **Haskell.** Рекурсивный спуск: `parseExpr -> parseAdd -> parseMul
-> parseAtom`. Каждый уровень возвращает `(значение, остаток-токенов)`,
паттерн-матчинг используется для разбора токенов. Обрабатываются +, -,
*, /, скобки, ошибки (деление на ноль, неожиданный символ, лишние
токены).

2.2 **Scala.** Алгебраический тип `Tree = Empty | Node(v, l, r)`,
операции `insert`, `contains`, `inOrder`, `height` реализованы через
рекурсивный pattern matching. Дерево строится свёрткой списка значений
через `foldLeft`.

2.3 **Scheme.** Классическая рекуррентная формула: `hanoi(n) = hanoi(n-1)
+ 1 + hanoi(n-1)`. Возвращается список ходов, затем распечатывается.
Считается общее число перемещений.

2.4 **Lua.** Рекурсивный бэктрекинг с тремя хеш-таблицами: занятые
колонки, диагонали `row+col`, диагонали `row-col+n`. Перебор всех
расстановок N ферзей, вывод количества решений и первого найденного.

## Тема 3. Ввод/вывод в консоль и файл

Папка: `3_io/`

| № | Задача | Язык | Папка |
|---|--------|------|-------|
| 1 | Подсчет частот слов в файле, запись отчета | D | `task_1_d` |
| 2 | Статистика по числовой колонке CSV | Julia | `task_2_julia` |
| 3 | Разбор лог-файла регулярками | Perl | `task_3_perl` |
| 4 | Парсер и сериализатор INI | Ruby | `task_4_ruby` |

3.1 **D.** Файл читается целиком, приводится к нижнему регистру,
чистится от пунктуации, разбивается на токены. Используется
ассоциативный массив `int[string]` для частот, затем сортировка по
убыванию частоты и алфавиту. Ошибки чтения ловятся через try/catch,
вывод в файл.

3.2 **Julia.** Читает CSV-файл построчно, парсит вторую колонку в
`Float64`. Некорректные строки пропускаются с предупреждением, полностью
некорректный файл - ошибка. Результат (count, sum, mean, min, max,
skipped) пишется в файл.

3.3 **Perl.** Разбирает лог вида `IP METHOD PATH STATUS` регулярным
выражением, копит счетчики по статусам и IP. Отчет (общее число,
разбивка по статусам, топ-5 IP) пишется в файл. `die` при ошибках
открытия/закрытия.

3.4 **Ruby.** Парсер INI: секции в `[...]`, пары `key=value`, комментарии
`;` и `#`. Строится `Hash` секций, потом сериализуется обратно. Ошибки
парсинга строк - предупреждения, отсутствие файла - исключение.

## Тема 4. Клиент-серверное взаимодействие

Папка: `4_client_server/`

| № | Задача | Язык | Папка |
|---|--------|------|-------|
| 1 | TCP-эхо-сервер на несколько подключений | ODIN | `task_1_odin` |
| 2 | TCP-клиент с ретраями подключения | Zig | `task_2_zig` |
| 3 | TCP-клиент с таймаутом | Erlang | `task_3_erlang` |
| 4 | TCP-клиент с ретраями через BSD-сокеты | Objective-C | `task_4_objective_c` |

4.1 **ODIN.** Сервер слушает `127.0.0.1:8080`, принимает до 3 клиентов
последовательно, читает данные в буфер до 4 КБ и отправляет обратно.
Ошибки `listen/accept/recv/send` обрабатываются.

4.2 **Zig.** Клиент подключается к `127.0.0.1:8080` с 3 попытками и
паузой 500 мс. Отправляет фиксированное сообщение, читает до 1024 байт.
Ошибки подключения/чтения/записи - в stderr.

4.3 **Erlang.** TCP-клиент на `gen_tcp` из стандартной библиотеки.
До 3 попыток подключения с таймаутом 1000 мс и паузой 1 секунда.
После подключения - отправка сообщения и чтение ответа с таймаутом
5000 мс. При истечении - печать "timeout waiting for response".

4.4 **Objective-C.** Клиент на BSD-сокетах: `socket`, `connect`, `send`,
`recv`. До 3 попыток с паузой 1 секунда. Все ошибки (socket/connect/send/
recv) логируются через `NSLog` с `strerror`.

## Тема 5. Конвертация данных

Папка: `5_convert/`

| № | Задача | Язык | Папка |
|---|--------|------|-------|
| 1 | Двусторонняя конвертация CSV <-> JSON | Groovy | `task_1_groovy` |
| 2 | Список целых <-> S-выражение | ML | `task_2_ml` |
| 3 | Ассоциативный список <-> строки ключ=значение | Lisp | `task_3_lisp` |
| 4 | Конвертация чисел между системами счисления | Mojo | `task_4_mojo` |

5.1 **Groovy.** `csvToJson` парсит строки CSV, строит список
ассоциативных массивов, вручную сериализует в JSON с экранированием.
`jsonToCsv` - обратная операция через регулярные выражения, собирает
объединенный набор ключей и печатает таблицу.

5.2 **ML.** Рекурсивная `listToSexp` собирает `(1 2 3 4 5)` из списка
int. `sexpToList` чистит скобки, разбивает по пробелам, парсит числа,
обрабатывает некорректные токены. Пустой список обрабатывается отдельно.

5.3 **Lisp.** `alist-to-string` пишет пары `key=value` по одной на строку
через `with-output-to-string`. `string-to-alist` читает построчно через
`with-input-from-string`, ищет `=`, собирает alist. Проверяется
round-trip на равенство.

5.4 **Mojo.** Прямые преобразования: `Int -> String` в hex, `String ->
Int` с base=16, `Float64 -> Int`, `Int -> Float64`. Ошибки
преобразования (некорректная строка, переполнение) обрабатываются через
`raises`.
