# Параллельные банковские переводы с проверкой инварианта

**Тема:** Многопоточность - Kotlin

## Описание задачи

5 счетов с начальным балансом 1000. 4 потока делают по 1000 случайных
переводов: выбирают два разных счета, случайную сумму, переводят.
Сумма балансов всех счетов должна оставаться неизменной - это
инвариант, который проверяется после работы всех потоков.

## Синхронизация

Каждый счет защищен `ReentrantLock`. При переводе нужно захватить два
замка - исходного и целевого счета. Если потоки захватывают замки в
произвольном порядке, возникает классическая проблема deadlock:
поток A держит замок 1 и ждет замок 2, поток B держит замок 2 и ждет
замок 1. Оба висят вечно.

Решение - фиксированный порядок захвата: всегда сначала меньший `id`.
Тогда для любой пары счетов все потоки берут замки в одном и том же
порядке, и циклическое ожидание невозможно. Порядок реализован через
`if (from.id < to.id) ... else ...`.

`withLock` из `kotlin.concurrent` - расширение стандартной библиотеки:
захватывает `ReentrantLock`, выполняет блок, отпускает замок. В
отличие от ручного `lock()`/`unlock()`, `withLock` безопасен при
исключениях - `unlock` вызывается в `finally`.

Проверка `from.balance >= amount` не дает уйти в минус. Внутри парных
замков это атомарно.

## Формат входных и выходных данных

Входных данных нет (число счетов, потоков и переводов - константы).
Выходные данные: начальная и конечная суммы, флаг сохранения
инварианта, финальные балансы.
